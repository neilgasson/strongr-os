# M0/M1/M2.2 Threat Model

| Threat | Control |
|---|---|
| Cross-tenant record linkage | Composite organization-scoped foreign keys plus negative tests |
| Direct browser bypass of review gates | No browser DML grants; narrow security-definer commands |
| Stolen low-assurance session approves content | AAL2 enforced for policy, review, approval, revocation, and export |
| AI grants authority | Worker may record checks/drafts only; human commands own review and approval |
| Automated pattern checks are mistaken for pastoral judgment | Checks produce versioned evidence only; separate Scripture, theology, and editorial human approvals remain mandatory |
| Approved content changes later | Immutable payload and exact stored payload hash |
| Approval points to changing evidence | Append-only evidence and exact join records |
| Duplicate AI/export side effects | Advisory-lock idempotency, transactional outbox, stable event ID, and one immutable delivery receipt |
| Worker crashes while holding work | Expiring lease, random per-claim token, attempt counter, and `SKIP LOCKED` recovery |
| Stale worker acknowledges recovered work | Ack/fail require the current unexpired lease token |
| Poison event retries forever | Maximum-attempt transition to visible dead letter plus critical alert |
| Operational logs expose private content | Structured logs contain IDs, counts, reason/error codes, and correlation IDs only |
| Audit tampering | Append-only audit trigger and no browser mutation grants |
| Service-role misuse | Server-only credential; worker-only check command; no client exposure |
| Sensitive content leaks into audit | Audit stores identifiers, state summaries, and reason codes—not raw scripts or private text |
| Browser uploads, replaces, deletes, or lists media | No browser Storage mutation policy; client boundary scan rejects mutation, public URL, and list operations |
| Public media exposure | Reproducible bucket configuration fixes `public = false`; only canonical artifact paths have an authenticated read policy |
| Cross-tenant object access | Opaque path includes organization/package/artifact UUIDs; Storage RLS joins the exact path to canonical tenant metadata and active membership |
| Service-upload ownership is trusted as tenant authority | Storage policy ignores `owner_id`; canonical database metadata and current membership are authoritative |
| Managed Storage metadata is changed directly | CI rejects DML against `storage.buckets` and `storage.objects`; future byte operations must use supported Storage APIs |
| Media bytes silently change | Write-once paths, immutable checksum metadata, strict WAV byte validation, and checksum revalidation on conflict/replay |
| Package is swapped after media intent | Composite tenant foreign key and immutable job identity bind one exact M1 production package |
| Partial database/object failure is hidden | Explicit reconciliation event model records ambiguous upload, missing/orphan object, and checksum mismatch states |
| Automated media is treated as human-approved | Worker evidence, human media review, and AAL2 staged release records remain separate authority layers |
| Service role writes governed tables directly | Explicit table DML revocation; exact M2.1 worker commands are the only media mutation surface |
| Upload succeeds but database completion fails | Stable preallocated path, no overwrite, lease recovery, exact byte download/revalidation, and append-only reconciliation evidence |
| Database artifact exists but object is missing | Replay verifies the canonical object before acknowledgement and records a blocked missing-object event |
| Authenticated retrieval becomes bucket enumeration | Storage policy permits only authenticated object-get operations and joins the exact object path to canonical tenant metadata; listing is not authorized |
| Client forges review integrity metadata | The review command constructs the evidence hash inside PostgreSQL from the canonical artifact and authenticated reviewer |
| Client stages an unreviewed or changed artifact | The staging command resolves the exact unrevoked package, canonical succeeded artifact, approved review, output specification, and reconciliation state inside one transaction |
| Staged manifest omits or substitutes authority | PostgreSQL constructs and hashes the immutable manifest; clients supply only bounded release configuration |
| Low-assurance session stages or revokes | Staging and revocation re-evaluate active membership, exact permission, and real AAL2 in the database |
| Service role assumes human authority | Human review, staging, and revocation commands revoke service-role execution and grant only the authenticated role |
| Revoked staged authority is silently recreated | Append-only revocation plus advisory-locked replay rules reject restaging a revoked bundle |

Residual risks before launch include M2.3 independent object-byte backup,
disposable restore, inventory and remote acceptance; deployment-platform secret
management; provider-specific monitoring; rate limiting; and operational
privacy procedures. Publication and production deployment remain outside M2.
